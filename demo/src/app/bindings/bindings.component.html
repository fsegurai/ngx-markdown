Loading and Errors

The `markdown` component emits `load` (the loaded `src` content), `ready` (once rendered) and `error`. `error` emits a `MarkdownError` (`Error | HttpErrorResponse | string`): a failed `src` request emits the `HttpErrorResponse`, which is not an `Error`. ```typescript onError(error: MarkdownError): void { const message = error instanceof HttpErrorResponse ? `HTTP ${error.status}` : String(error); } ``` `data` and `src` follow these rules: - a non-empty `data` wins over `src` (with a one-time warning); - `data = ''` together with a `src` loads the `src`; `data = ''` alone clears the output; - only the latest request is rendered: clearing `data` and `src` cancels a request still in flight and empties the output. Try it below: load a file, a missing file, or clear both.

`MarkdownService.reload()` renders every component again, including the content transcluded between the `<markdown>` tags (see [Re-render](/re-render)).

Relative Links

By default, relative URLs in the content resolve against the page, as in 21.x. With `srcRelativeLink`, the relative links and images of a `src` file resolve against the file itself, so the Markdown works as it does on GitHub: ```html <markdown src="app/bindings/remote/relative/guide.md" srcRelativeLink /> ``` `baseUrl` sets the base URL explicitly, for `data` too (and wins over `srcRelativeLink`). End a folder with `/`: `docs/guide` is a file, so URLs resolve against `docs/`. Absolute, protocol-relative (`//`), fragment (`#`), `mailto:`, `data:`, `/routerLink:` and `/localFile:` URLs are left untouched. ```html <markdown [data]="markdown" baseUrl="app/bindings/remote/relative/" /> ```

Front-matter

A block between `---` lines (YAML) or `+++` lines (TOML) at the very start of the content is front-matter. By default it is rendered as Markdown, as in 21.x (a horizontal rule, then a heading). With `frontMatter`, it is stripped before parsing, and the `metadata` output emits its parsed `data` and its `raw` text on each render: ```html <markdown src="app/bindings/remote/front-matter.md" frontMatter (metadata)="metadata.set($event)" /> ``` `data` holds a safe subset: strings, numbers, booleans, `null`, `[a, b]` arrays and `- item` lists. Any other value stays a raw string; nothing is evaluated.

Pipe Usage

Using `markdown` pipe to transform markdown to HTML allow you to chain pipe transformations and will update the DOM when value changes. It is important to note that, because the `marked` parsing method returns a `Promise`, it requires the use of the `async` pipe. In the following example using the synthax above, `typescriptMarkdown` property does not contain any `back-ticks` to set the content language but will be chain with `language` pipe instead to specify synthax highlights language along with `markdown` pipe for conversion
